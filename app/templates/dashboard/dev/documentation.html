Documentation API Boost Reseller

Bienvenue dans la documentation officielle de l'API Boost Reseller (v1). Cette API vous permet d'automatiser la gestion de votre boutique : produits, commandes, clients, statistiques, webhooks et bien plus. Toutes les requêtes sont en HTTPS et les réponses sont en JSON.

Introduction

L'API Boost Reseller est une API REST qui utilise les standards HTTP (GET, POST, PATCH, DELETE). Toutes les réponses sont au format JSON encodé en UTF-8.

Avec cette API, vous pouvez :

  • Récupérer et modifier les informations de votre boutique.
  • Créer, modifier et supprimer des produits en masse.
  • Consulter les commandes et mettre à jour leur statut.
  • Lister vos clients inscrits.
  • Obtenir des statistiques détaillées sur vos ventes.
  • Recevoir des notifications en temps réel via webhooks.
  • Intégrer Boost Reseller avec vos outils (Zapier, Make, ERP, CRM...).
Prérequis : Pour utiliser l'API, vous devez disposer d'une clé API valide. Chaque clé possède des permissions (scopes) précises que vous définissez à la création.

Authentification

Toutes les requêtes doivent inclure votre clé API dans le header Authorization au format Bearer :

Authorization: Bearer bsk_live_votre_cle_ici
Ne partagez jamais votre clé API. Ne la committez pas dans un dépôt Git public. Ne l'incluez pas dans du code côté client (JavaScript navigateur). Utilisez-la uniquement depuis votre serveur.

Exemple d'appel authentifié

curl https://reseller.boostcentral.world/api/v1/boutique \
  -H "Authorization: Bearer bsk_live_xxxx"

URL de base

Toutes les requêtes API doivent être faites sur cette URL :

https://reseller.boostcentral.world/api/v1

Format des réponses

Les réponses de succès sont renvoyées avec un code HTTP 200 (ou 201 pour les créations) et un contenu JSON. Les erreurs utilisent des codes HTTP standards.

Réponse de succès

{
  "success": true,
  "data": {
    "id": "abc-123",
    "nom": "T-shirt Nike"
  }
}

Réponse d'erreur

{
  "success": false,
  "error": {
    "code": "invalid_scope",
    "message": "Votre cle ne possede pas le scope 'produits:write'"
  }
}

Rate limits

Pour garantir la stabilité du service, chaque clé API est limitée à :

Type de requêteLimite
Requêtes GET (lecture)1 000 / heure
Requêtes POST/PATCH/DELETE (écriture)200 / heure
Rafale maximale30 / minute

Les headers X-RateLimit-Limit, X-RateLimit-Remaining et X-RateLimit-Reset sont renvoyés dans chaque réponse.

En cas de dépassement, vous recevrez un code 429 Too Many Requests. Attendez le temps indiqué dans le header Retry-After avant de réessayer.

Scopes & permissions

Chaque clé API possède un ensemble de scopes qui définissent ce qu'elle peut faire :

ScopeDescription
boutique:readLire les informations de votre boutique
boutique:writeModifier les informations de votre boutique
produits:readLister et consulter vos produits
produits:writeCréer, modifier et supprimer des produits
commandes:readConsulter les commandes de vos clients
commandes:writeModifier le statut des commandes
clients:readLister vos clients inscrits
stats:readAccéder aux statistiques de vente
Principe du moindre privilège : Donnez uniquement les scopes strictement nécessaires à votre usage. Si votre app ne fait que lire les commandes, ne lui donnez pas commandes:write.

Bonnes pratiques

  • Une clé par environnement : une clé pour le développement, une pour la production.
  • Rotation régulière : révoquez et régénérez vos clés tous les 6 mois.
  • Stockage sécurisé : utilisez des variables d'environnement, jamais en clair dans le code.
  • Révoquez immédiatement toute clé compromise depuis l'interface.
  • Idempotence : pour les POST critiques, envoyez un header X-Idempotency-Key pour éviter les doublons.
  • Gestion des erreurs : implémentez des retry avec backoff exponentiel pour les erreurs 5xx et 429.

Webhooks - Introduction

Les webhooks permettent à Boost Reseller de notifier votre serveur en temps réel à chaque événement (nouvelle commande, paiement reçu...).

Comment ça marche ?

  1. Vous créez un webhook dans Webhooks.
  2. Vous recevez un secret de signature (à conserver).
  3. À chaque événement, on envoie une requête POST à votre URL.
  4. Vous vérifiez la signature avec le header X-Boost-Signature.

Réponse attendue

Votre serveur doit répondre avec un code HTTP 2xx (200, 201, 204...). Tout autre code sera considéré comme un échec.

Webhooks - Événements

ÉvénementDescription
commande.creeeUn client passe une nouvelle commande
commande.confirmeeVous confirmez une commande
commande.en_livraisonCommande en cours de livraison
commande.livreeCommande livrée
commande.annuleeCommande annulée
paiement.recuUn paiement est validé
client.inscritUn nouveau client s'inscrit
avis.ajouteUn client laisse un avis
produit.stock_basUn produit est presque épuisé

Exemple de payload reçu

POST /votre-endpoint HTTP/1.1
Content-Type: application/json
X-Boost-Event: commande.creee
X-Boost-Signature: t=1729000000,v1=abc123...
X-Boost-Delivery: 5f8a9c...

{
  "event": "commande.creee",
  "timestamp": 1729000000,
  "data": {
    "reference": "CMD-A3F8B2C1D4E5",
    "client_nom": "Jean Dupont",
    "client_telephone": "658033690",
    "total": 25000,
    "statut": "en_attente"
  }
}

Webhooks - Signature HMAC

Chaque requête est signée avec le secret de votre webhook. Vérifiez systématiquement la signature pour vous assurer que la requête vient bien de Boost Reseller.

Comment vérifier

  1. Récupérez les headers X-Boost-Signature et X-Boost-Event.
  2. Extrayez le timestamp et la signature v1 du header (t=xxx,v1=xxx).
  3. Construisez le message : timestamp + "." + body_brut.
  4. Calculez le HMAC-SHA256 avec votre secret.
  5. Comparez avec la signature reçue.

Exemple Python

import hashlib
import hmac

def verifier_signature(secret, timestamp, body_brut, signature_recue):
    message = f"{timestamp}.{body_brut}"
    signature_calculee = hmac.new(
        secret.encode("utf-8"),
        message.encode("utf-8"),
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(signature_calculee, signature_recue)
Important : Utilisez toujours hmac.compare_digest (ou équivalent) pour comparer les signatures. Cela évite les attaques par timing.

Exemple Python complet

import requests

API_KEY = "bsk_live_xxxx"
BASE = "https://reseller.boostcentral.world/api/v1"

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json"
}

# Lister les produits
r = requests.get(f"{BASE}/produits", headers=headers)
produits = r.json()["data"]
print(f"{produits['total']} produits")

# Creer un produit
nouveau = {
    "nom": "Casquette",
    "prix": 5000,
    "stock": 100
}
r = requests.post(f"{BASE}/produits", headers=headers, json=nouveau)
print(r.json())

# Lister les commandes en attente
r = requests.get(f"{BASE}/commandes?statut=en_attente", headers=headers)
commandes = r.json()["data"]["commandes"]
for c in commandes:
    print(f"{c['reference']} - {c['client_nom']}")

Exemple JavaScript (Node.js)

const API_KEY = "bsk_live_xxxx";
const BASE = "https://reseller.boostcentral.world/api/v1";

async function listerProduits() {
  const r = await fetch(`${BASE}/produits`, {
    headers: { "Authorization": `Bearer ${API_KEY}` }
  });
  const data = await r.json();
  console.log(data.data.total, "produits");
}

async function creerProduit() {
  const r = await fetch(`${BASE}/produits`, {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${API_KEY}`,
      "Content-Type": "application/json"
    },
    body: JSON.stringify({ nom: "Casquette", prix: 5000, stock: 100 })
  });
  console.log(await r.json());
}

listerProduits();

Questions fréquentes

Ma clé API ne fonctionne pas, que faire ?

Vérifiez que : (1) la clé n'a pas été révoquée, (2) vous avez bien mis Bearer avant la clé, (3) la clé possède le bon scope pour l'action demandée.

Je reçois une erreur 403 forbidden_scope, que faire ?

Votre clé n'a pas le scope nécessaire. Allez dans Clés API, révoquez l'ancienne et créez-en une nouvelle avec les scopes adéquats.

Combien de clés API puis-je créer ?

Vous pouvez créer jusqu'à 10 clés actives simultanément.

Y a-t-il un SDK officiel ?

Le SDK Python est disponible au téléchargement dans la section SDK. Les versions JavaScript et PHP sont en développement.

Comment tester mes appels sans risque ?

Utilisez l'onglet Playground pour tester vos appels depuis le dashboard.

Comment recevoir des notifications en temps réel ?

Configurez un webhook dans la section dédiée. Nous vous enverrons une requête HTTP POST sur votre URL à chaque événement.

Puis-je utiliser plusieurs webhooks ?

Oui, vous pouvez créer plusieurs webhooks avec des événements différents. Chacun possède son propre secret de signature.

Les paiements en ligne sont-ils supportés ?

Oui, l'intégration Mysoleas permet d'encaisser automatiquement les paiements via MTN Mobile Money, Orange Money et cartes bancaires.

Que faire en cas de problème non résolu ?

Contactez le support technique via WhatsApp avec : l'endpoint appelé, la clé (préfixe uniquement), le code HTTP, et le message d'erreur.
